## 0. 基本原則

1. 範圍：會計學、貨幣銀行學、票據法、銀行法。
2. 題目來源分三類，**永遠分開標示，不混稱**：
   - `BANK_EXAM` 公股銀行甄試題（須有官方公告來源）
   - `FIT_REFERENCE` FIT 參考試題（獨立標示「FIT 參考試題，非銀行甄試題」）
   - `DEMO` 自編示範題（標示「自編示範題，非歷屆真題」，答案標示「自編參考答案，非官方答案」）
3. 缺答案、缺來源、缺題號時**明確顯示「缺少」**，系統不推測、不自動補答案。
4. 不編造官方答案與法條內容。法條引用一律需有「法規名稱＋條號＋核對日期＋核對來源網址」，未核對者顯示「條文未核對」。
5. 在無法確認來源使用條件前，題庫只放少量自編示範題；真題匯入功能做好但不預載真題。

## 1. 來源使用條件初步檢查（2026-11-17）

| 項目 | 結果 |
|---|---|
| 公股銀行甄試多委託台灣金融研訓院辦理試務 | 簡章可見（如合作金庫、臺灣銀行簡章），但**未找到**官方「歷屆試題下載」頁或公開授權聲明 |
| 台灣金融研訓院網站之著作權／重製條款 | **未能確認**，需至官網頁尾「著作權聲明／網站政策」查閱或去函詢問 |
| 第三方考古題網站（補習班等） | 非官方來源，答案正確性與授權皆不明，**不作為題庫來源**，最多作為尋找原卷的線索 |
| 著作權法第 9 條第 1 項第 5 款（依法令舉行之考試試題不受保護） | 公股銀行（公司）自辦之人員甄試是否屬「依法令舉行之考試」，**我無法判斷**，需由你或法律專業人士確認 |

**結論**：目前無法確認可在產品內重製試題 → 第 1 階段以約 20 題自編示範題完成系統。

### 3.3 `law_citations` 法條引用（一題可多筆）
| 欄位 | 說明 |
|---|---|
| question_id | |
| law_name | 法規名稱（如「票據法」） |
| article_no | 條號（如「第 13 條」） |
| version_note | 引用的版本（考試當時／現行） |
| checked_on | 核對日期（空＝未核對，畫面顯示「條文未核對」） |

不儲存或顯示未經核對的條文內容。

### 3.4 `duplicate_groups` 重複群組
`id`, `canonical_question_id`（代表題）, `confirmed`（是否人工確認）, `note`。
練習時可選「合併重複題」：同組只出一題，但詳情與解析頁列出所有出處。

### 3.5 作答相關（第 1 階段為單機單使用者）
- `attempts`：`id`, `mode`（PRACTICE/EXAM/RETRY_WRONG）, `filters`(JSON), `time_limit_sec`, `started_at`, `submitted_at`, `score`
- `attempt_answers`：`attempt_id`, `question_id`, `chosen`, `is_correct`（題目缺官方答案時為 null，不計分並標示「無法判分」）, `time_spent_sec`
- `bookmarks`：`question_id`, `created_at`, `note`
- `wrong_book`：`question_id`, `wrong_count`, `correct_streak`, `last_attempt_at`

### 3.6 匯入相關
- `import_jobs`：`id`, `file_name`, `file_type`(PDF/CSV), `paper_meta`(JSON), `raw_text`, `status`（UPLOADED/PARSED/REVIEWING/PUBLISHED）, `created_at`
- `import_items`：`job_id`, 擷取出的題目欄位（同 questions），`warnings`(JSON)，`edited`(bool)

### 3.7 `source_checks` 來源使用條件
見第 6 節欄位。

### 3.8 CSV 匯入格式（草案）
```
source_type,bank,year,exam_name,subject,topic,number,stem,option_a,option_b,option_c,option_d,official_answer,answer_status,paper_url,answer_url,explanation,law_at_exam,law_recheck
```
空白答案自動記為 `MISSING`。

## 4. 技術選型（建議）

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | **Next.js（App Router）＋ TypeScript** | 前後端同一專案，一個指令 `npm run dev` 即可在本機執行 |
| 介面 | Tailwind CSS | 方便做手機／桌機響應式 |
| 資料庫 | **SQLite**（透過 Prisma ORM） | 本機零設定、單一檔案好備份；日後要上線可換 PostgreSQL |
| PDF 擷取 | pdfjs-dist（文字層擷取） | 文字型 PDF 可直接擷取；**掃描影像 PDF 第 1 階段不支援 OCR**，列入第 2 階段 |
| CSV | papaparse | |
| 圖表 | Recharts | 統計頁正確率 |
| 測試 | Vitest（題目切分、計分邏輯）＋ Playwright（主要流程） | |
| 管理驗證 | 環境變數 `ADMIN_PASSWORD`＋簽章 cookie | 第 1 階段單機用，夠用即可 |

需求：Node.js 20 以上。

## 10. 第 2 階段：限時模擬考（2026-11-17）

### 10.1 決定
| 項目 | 內容 |
|---|---|
| 預設考試 | 會計學＋貨幣銀行學 80 題／90 分鐘；票據法＋銀行法 50 題／60 分鐘 |
| 出題 | 兩科平均分配，不足時由另一科補足；同一重複群組只出一題；預設排除缺少官方答案的題目；可選來源類型 |
| 題庫不足 | 以現有題數進行，時限不變，開考前提示 |
| 計時 | 截止時間存在伺服器（`attempts.deadline_ms`），頁面重新整理不重算；以伺服器時間校正使用者電腦時鐘 |
| 時間到 | 前端自動交卷；未開頁面者於下次開啟該考試、模擬考頁或統計頁時由伺服器以 TIMEOUT 交卷；截止後 5 秒寬限，之後拒絕作答 |
| 計分 | 未作答計為答錯（不加入錯題本）；缺答案題不計分；分數＝答對／計分題數×100 |

## 11. 第 3 階段：依真實考試各科比例出題（2026-11-17）

### 11.1 原則
- 系統不內建、不推測任何銀行的各科題數比例。
- 比例來源：（1）已發布且「已與原卷核對」的銀行甄試題統計（FIT 參考試題、示範題不列入）；（2）使用者手動設定。
- 兩者皆無時以平均分配，並在模擬考頁、結果頁明確標示。

### 11.2 計算方式
- 自動統計：依篩選條件（銀行、起訖年度）加總各試卷中屬於該考試科目的題數；同一題出現在不同試卷各算一次（比例描述的是試卷內容）。
- 題數換算：最大餘數法，總和恰為設定題數（80 或 50）。
- 題庫不足：某科可出題數不足時，差額依比例分給其他仍有題目的科目；比例為 0 的科目只在其他科都用完時才補題。
- 作答紀錄保存比例來源、預計題數、實際題數（`attempts.filters` 中的 `plan`）。

### 11.3 頁面與資料
- 新增 `/admin/exam-settings`：每種預設考試的比例依據（自動／手動／平均）、自動統計篩選（銀行、年度）、手動比例、統計結果與試卷明細。
- `/exam`：每張卡片顯示比例來源與「比例／預計／題庫可出／本次實際」表；自訂模擬考可選依真題統計或平均。
- 結果頁：顯示出題比例與各科預計／實際題數。
- 新增資料表 `exam_settings`（preset_key、ratio_mode、manual_weights、basis_bank、basis_year_from、basis_year_to）。

- 依「單一試卷」重現原卷題數（目前為多份試卷加總後的比例）

## 12. 手機連線、QR code 與 PWA（2026-11-17）

- 不部署到公開網路（真題使用條件未確認、資料存在本機），因此沒有固定公開網址。
- `npm run lan`：建置後以 `0.0.0.0` 啟動正式模式，終端機印出區網網址與 QR code；`npm run lan:dev` 為開發模式（`allowedDevOrigins` 自動加入本機區網 IP）。
- `/connect`：依電腦區網 IP（或目前連線網址）產生 QR code，可輸入其他網址產生 QR code，並提供 iPhone、Android、電腦的安裝說明與「安裝 App」按鈕。
- PWA：`app/manifest.ts`（名稱、standalone、主題色、圖示、捷徑：題庫／模擬考／錯題複習）、`public/icons/*`、Apple 主畫面設定、`public/sw.js`（只快取圖示與離線提示頁，頁面一律向伺服器取最新內容）、`public/offline.html`。
- 限制：Service Worker 與完整安裝需要 https 或 localhost；透過區網 http 連線時，iPhone 可加入主畫面，Android 為主畫面捷徑。
