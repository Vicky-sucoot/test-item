## 0. 基本原則

1. 範圍：會計學、貨幣銀行學、票據法、銀行法。
2. 題目來源分三類，**永遠分開標示，不混稱**：
   - `BANK_EXAM` 公股銀行甄試題（須有官方公告來源）
   - `FIT_REFERENCE` FIT 參考試題（獨立標示「FIT 參考試題，非銀行甄試題」）
   - `DEMO` 自編示範題（標示「自編示範題，非歷屆真題」，答案標示「自編參考答案，非官方答案」）
3. 缺答案、缺來源、缺題號時**明確顯示「缺少」**，系統不推測、不自動補答案。
4. 不編造官方答案與法條內容。法條引用一律需有「法規名稱＋條號＋核對日期＋核對來源網址」，未核對者顯示「條文未核對」。
5. 在無法確認來源使用條件前，題庫只放少量自編示範題；真題匯入功能做好但不預載真題。

## 1. 來源使用條件初步檢查（2026-11-17）

| 項目 | 結果 |
|---|---|
| 公股銀行甄試多委託台灣金融研訓院辦理試務 | 簡章可見（如合作金庫、臺灣銀行簡章），但**未找到**官方「歷屆試題下載」頁或公開授權聲明 |
| 台灣金融研訓院網站之著作權／重製條款 | **未能確認**，需至官網頁尾「著作權聲明／網站政策」查閱或去函詢問 |
| 第三方考古題網站（補習班等） | 非官方來源，答案正確性與授權皆不明，**不作為題庫來源**，最多作為尋找原卷的線索 |
| 著作權法第 9 條第 1 項第 5 款（依法令舉行之考試試題不受保護） | 公股銀行（公司）自辦之人員甄試是否屬「依法令舉行之考試」，**我無法判斷**，需由你或法律專業人士確認 |

**結論**：目前無法確認可在產品內重製試題 → 第 1 階段以約 20 題自編示範題完成系統。

### 2.4 錯題本／收藏 `/review`
分頁「錯題」「收藏」，每題顯示錯誤次數、最後作答日；可勾選後「重練所選」。答對連續 N 次（預設 2）自動移出錯題本（可設定）。

### 2.5 限時模擬考 `/exam/setup` → `/exam/:id`
```

      來源 [✓銀行甄試 □FIT □示範]  [開始]

        時間到自動交卷；中途離開可續考
```

### 2.6 統計 `/stats`
各科正確率長條圖、近 30 天作答趨勢、各主題正確率表、作答紀錄列表（日期、模式、題數、得分、可點進看結果）。

### 2.7 題目詳情 `/q/:id`
完整顯示所有中繼資料：來源試卷、原卷網址、題號、官方答案、資料核對狀態、解析審核狀態、法規欄位、重複群組內所有出處。


## 3. 資料欄位

### 3.1 `exam_papers` 試卷（一份公告試卷一筆）
| 欄位 | 說明 |
|---|---|
| id | |
| source_type | `BANK_EXAM` / `FIT_REFERENCE` / `DEMO` |
| bank | 銀行名稱（FIT/示範為空） |
| year | 民國年度 |
| exam_name | 甄試名稱（如「113 年度新進人員甄試」） |
| position | 職缺／類別（選填） |
| subject_label | 原卷科目名稱（如「綜合科目（含票據法、銀行法）」） |
| paper_url | 原始試卷網址 |
| answer_url | 官方答案網址（無則空） |
| announcement_url | 甄試公告網址 |
| exam_date | 考試日期 |
| source_check_id | 對應來源使用條件檢查表 |
| note | |

### 3.2 `questions` 題目（每份試卷中的每一題一筆，重複題也各自一筆）
| 欄位 | 說明 |
|---|---|
| id | |
| paper_id | → exam_papers |
| number_in_paper | 原卷題號（缺少則空並標示） |
| subject | `ACCOUNTING` / `MONEY_BANKING` / `NEGOTIABLE_INSTRUMENTS` / `BANKING_ACT` |
| topic | 主題（如「存貨」「貨幣供給」「背書」「存款準備」） |

| options | A–D（JSON） |
| official_answer | 官方答案；空值＝缺少 |
| answer_status | `OFFICIAL` 官方答案 / `OFFICIAL_AMENDED` 官方更正（含一題多答、送分）/ `MISSING` 缺少 / `SELF_WRITTEN` 自編參考答案 |
| answer_note | 例：「官方公告更正為 B 或 C 皆給分」 |
| verify_status | 資料核對：`UNVERIFIED` 未核對 / `VERIFIED` 已與原卷核對 / `MISMATCH` 與原卷不符待修 |
| verified_by, verified_at | |
| explanation | 解析 |
| explanation_status | `NONE` 無 / `DRAFT` 草稿 / `REVIEWED` 已審核 |
| explanation_reviewed_by/at | |
| duplicate_group_id | 重複群組（同一題目出現在不同試卷時共用） |
| status | `DRAFT` / `PUBLISHED` / `ARCHIVED` |
| law_at_exam | 考試當時適用法規（名稱＋版本／修正公布日），僅票據法、銀行法必填 |
| law_recheck | 目前法規是否需重新核對：`NEEDS_RECHECK` / `CHECKED_NO_CHANGE` / `CHECKED_CHANGED` / `UNKNOWN` |
| law_recheck_date | 最近核對日期 |

### 3.3 `law_citations` 法條引用（一題可多筆）
| 欄位 | 說明 |
|---|---|
| question_id | |
| law_name | 法規名稱（如「票據法」） |
| article_no | 條號（如「第 13 條」） |
| version_note | 引用的版本（考試當時／現行） |
| checked_on | 核對日期（空＝未核對，畫面顯示「條文未核對」） |
| checked_source_url | 核對來源（建議全國法規資料庫） |

不儲存或顯示未經核對的條文內容。

### 3.4 `duplicate_groups` 重複群組
`id`, `canonical_question_id`（代表題）, `confirmed`（是否人工確認）, `note`。
練習時可選「合併重複題」：同組只出一題，但詳情與解析頁列出所有出處。

### 3.5 作答相關（第 1 階段為單機單使用者）
- `attempts`：`id`, `mode`（PRACTICE/EXAM/RETRY_WRONG）, `filters`(JSON), `time_limit_sec`, `started_at`, `submitted_at`, `score`
- `attempt_answers`：`attempt_id`, `question_id`, `chosen`, `is_correct`（題目缺官方答案時為 null，不計分並標示「無法判分」）, `time_spent_sec`
- `bookmarks`：`question_id`, `created_at`, `note`
- `wrong_book`：`question_id`, `wrong_count`, `correct_streak`, `last_attempt_at`

### 3.6 匯入相關
- `import_jobs`：`id`, `file_name`, `file_type`(PDF/CSV), `paper_meta`(JSON), `raw_text`, `status`（UPLOADED/PARSED/REVIEWING/PUBLISHED）, `created_at`
- `import_items`：`job_id`, 擷取出的題目欄位（同 questions），`warnings`(JSON)，`edited`(bool)

### 3.7 `source_checks` 來源使用條件
見第 6 節欄位。

### 3.8 CSV 匯入格式（草案）
```
source_type,bank,year,exam_name,subject,topic,number,stem,option_a,option_b,option_c,option_d,official_answer,answer_status,paper_url,answer_url,explanation,law_at_exam,law_recheck
```
空白答案自動記為 `MISSING`。

## 4. 技術選型（建議）

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | **Next.js（App Router）＋ TypeScript** | 前後端同一專案，一個指令 `npm run dev` 即可在本機執行 |
| 介面 | Tailwind CSS | 方便做手機／桌機響應式 |
| 資料庫 | **SQLite**（透過 Prisma ORM） | 本機零設定、單一檔案好備份；日後要上線可換 PostgreSQL |
| PDF 擷取 | pdfjs-dist（文字層擷取） | 文字型 PDF 可直接擷取；**掃描影像 PDF 第 1 階段不支援 OCR**，列入第 2 階段 |
| CSV | papaparse | |
| 圖表 | Recharts | 統計頁正確率 |
| 測試 | Vitest（題目切分、計分邏輯）＋ Playwright（主要流程） | |
| 管理驗證 | 環境變數 `ADMIN_PASSWORD`＋簽章 cookie | 第 1 階段單機用，夠用即可 |

需求：Node.js 20 以上。

## 7. 需要你提供或決定的事項

1. **確認技術選型**（Next.js＋SQLite），或指定其他技術。
2. **銀行清單與優先順序**：上列銀行是否都要？是否納入中國輸出入銀行、其他公股機構？
3. **年度範圍**：例如近 5 年（民國 110–114 年）？
4. **原卷與答案檔**：你手上若已有 PDF 或網址，請提供（我不會自行從第三方網站抓題）。
5. **使用條件判斷**：是否由你向各銀行／金研院詢問重製授權，或取得法律意見？在確認前真題只會存成草稿，不對外顯示。
6. **綜合科目的切分**：原卷常把多科合為「綜合科目」，是否依題目內容各自歸入四科？
7. **主題分類表**：要用我提出的預設主題，或你有既定章節架構？
8. **解析撰寫與審核者**：誰負責審核解析？第 1 階段解析預設為「草稿」狀態。
9. **使用者範圍**：第 1 階段只給你自己在本機使用，是否正確？
10. **管理密碼**：本機以環境變數設定，不寫入程式碼庫。
11. **錯題移出規則**：連續答對幾次移出錯題本（預設 2 次）？
12. **模擬考預設**：每科題數與時間（預設 50 題 60 分鐘）？
